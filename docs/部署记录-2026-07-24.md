## 3. jAccount 接入

### 3.1 认证来源

思源 Compass 没有单独注册一套 jAccount OAuth 应用，而是复用同域门户 `portal` 已有的 OAuth 登录和 Flask 签名 session：

```text
/shengya/api/auth/jaccount/login
  -> /auth/jaccount/login
  -> jAccount OAuth
  -> /auth/jaccount/callback
  -> /shengya/api/auth/jaccount/callback
  -> 原请求页面
```

后端只验证门户签名 session 并读取 `jaccount` 和展示名，不保存 jAccount 密码或 OAuth access token，也不继承门户管理员身份。

### 3.2 管理员白名单来源

管理员身份不是根据教师或学生身份自动判断，而是由 ai4edu 根站点的 `portal` 项目维护 `ADMIN_JACCOUNTS` 白名单。

来源项目：

- 本机目录：`/Users/k/ai/course`
- SJTU GitLab：`git@git.ip.dev.sjtu.edu.cn:moran/course2026.git`
- GitHub 镜像：`git@github.com:zephyr221/course.git`
- 项目组件：`portal/`（上海交通大学 AI+教育教学资源管理平台）
- 源文件：`portal/deploy/portal.service`
- 服务器生效文件：`/etc/systemd/system/portal.service`

Git 历史来源：

- `15749ce9`（2026-05-31，`Add AI resource platform admin console`）首次加入 `moran,yzhu` 管理员名单。
- `eb5252ee`（2026-06-01，`Update admin access and console styling`）将名单扩展为当前值。

这两项变更都来自 `course2026` 的 portal 管理端开发历史，与思源 Compass 学生仓库无关。

门户在 OAuth 成功后仍会用 `username in ADMIN_JACCOUNTS` 生成 `is_admin`，供 portal 自己的管理端使用。思源 Compass 明确忽略该字段；jAccount 首次进入生涯助手时统一映射为 `student`。

生涯助手管理员由本项目数据库独立授权，不复用 portal 白名单。`admin` 是附加管理能力：管理员仍可填写问卷、查看自己的报告和反馈，同时可以进入管理后台。

管理员授权命令：

```bash
cd /opt/siyuan-compass/backend
.venv/bin/python scripts/manage_jaccount_admin.py add <jaccount> [<jaccount> ...]
.venv/bin/python scripts/manage_jaccount_admin.py remove <jaccount> [<jaccount> ...]
```

命令可以在账号首次登录前执行；首次登录会补充真实展示名，并保留已授予的角色。

## 4. DeepSeek 接入

生产环境配置：

```text
LLM_PROVIDER=deepseek
DEEPSEEK_BASE_URL=https://models.sjtu.edu.cn/api/v1
DEEPSEEK_MODEL=deepseek-chat
```

后端可以读取项目专用的 `DEEPSEEK_*` 变量，也可以复用服务器 `/etc/course-ai.env` 中的：

```text
AI_API_KEY
AI_API_BASE
AI_MODEL
```

密钥不在项目目录、Git 历史或本文档中。首次部署已通过最小请求验证实际响应模型为 `deepseek-chat`。

## 6. 前端构建

必须带子路径和生产认证开关构建：

```bash
cd frontend
VITE_BASE_PATH=/shengya/ \
VITE_API_BASE_URL=/shengya/api \
VITE_ENABLE_LOCAL_AUTH=false \
npm run build
```

构建后检查 `frontend/dist/index.html`，脚本和样式地址应以 `/shengya/assets/` 开头。

## 7. 更新流程

学生仓库继续作为产品开发上游；部署 fork 只维护校内认证、模型和服务器适配。

```bash
git fetch upstream
git switch sjtu-production
git merge upstream/main
```

合并后先在本地执行：

```bash
cd backend
.venv/bin/python -m pytest -q

cd ../frontend
npm run typecheck
VITE_BASE_PATH=/shengya/ \
VITE_API_BASE_URL=/shengya/api \
VITE_ENABLE_LOCAL_AUTH=false \
npm run build
```

发布代码时排除本地环境、依赖、数据库和离线镜像：

```bash
rsync -a \
  --exclude '.env' \
  --exclude '.git' \
  --exclude 'backend/.venv' \
  --exclude 'backend/.pytest_cache' \
  --exclude 'frontend/node_modules' \
  --exclude 'data/local-postgres' \
  --exclude '*.tar.gz' \
  --exclude '__pycache__' \
  ./ pj2-ext:/opt/siyuan-compass/
```

服务器更新后：

```bash
ssh pj2-ext '
  /opt/siyuan-compass/backend/.venv/bin/pip install -r /opt/siyuan-compass/backend/requirements.txt &&
  chown -R siyuan-compass:siyuan-compass /opt/siyuan-compass &&
  systemctl restart siyuan-compass
'
```

只有 Nginx 配置发生变化时才重新安装模板；必须先执行 `nginx -t`，成功后再 reload。

## 9. 回退原则

1. 发布前记录部署分支提交 SHA。
2. 代码问题优先切换到上一个已验证提交，再重新构建和发布。
3. 配置变更前保存单独备份；Nginx 备份不要放在 `sites-enabled` 中，避免被当作额外站点加载。
4. 不覆盖 `/etc/siyuan-compass.env`，除非本次任务明确是修改生产配置。
5. 数据库结构变更前先备份数据库。本次部署没有建立自动业务数据备份策略。

## 10. 当前边界

- 报告生成任务运行在 FastAPI 进程内；服务重启会中断正在生成的任务。
- 当前部署适合演示和小规模试用。
- `course2026/portal` 的管理员名单只作用于 portal；思源 Compass 不读取或复制该名单。
- 若未来迁移到独立云服务器，需要重新设计 jAccount 回调或可信身份转发，不能直接复制门户 session 密钥到不受控服务器。
- 项目后续业务功能以学生上游仓库为准，部署分支应尽量减少与业务代码的长期差异。
