# 部署与运维文档

## 1. 环境配置

项目只使用根目录 .env。先复制模板：

~~~bash
cp .env.example .env
~~~

至少配置：

~~~text
LLM_PROVIDER
KIMI_API_KEY 或 DEEPSEEK_API_KEY
AUTH_SECRET
ADMIN_PASSWORD
POSTGRES_PASSWORD
FRONTEND_ORIGINS
~~~

报告配额、任务租约、草稿保留、审计保留和语音配置都在 .env.example 中有说明。真实密钥只放在服务器 .env，不提交到 Git。

## 2. 账户配额设置

账户配额是按账号、按自然日计算的功能使用次数限制，不是数据库容量限制。

默认不限制：

~~~text
REPORT_GENERATION_DAILY_LIMIT=0
SPEECH_DAILY_LIMIT=0
~~~

设置为正数即可启用限制。例如：

~~~text
REPORT_GENERATION_DAILY_LIMIT=3
SPEECH_DAILY_LIMIT=20
REPORT_GENERATION_QUOTA_TIMEZONE=Asia/Shanghai
SPEECH_QUOTA_TIMEZONE=Asia/Shanghai
~~~

- 报告配额按创建生成任务计数，任务成功、失败或取消都会占用一次。
- 语音配额按提交转写请求计数。
- 删除报告、任务或其他业务数据不会返还当天已使用的额度。
- 到达上限时接口返回 429；下一个自然日自动重新计算。
- 修改 .env 后需要重启或强制重建后端容器。

## 3. 本地 Docker 开发

~~~bash
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs -f backend
~~~

访问：

- 前端：http://localhost:5173
- 后端：http://localhost:8000
- API 文档：http://localhost:8000/docs

停止开发容器：

~~~bash
docker compose -f docker-compose.dev.yml down
~~~

只有确认本地数据库无用时才使用 down -v，因为它会删除开发数据卷。

## 4. 服务器生产部署

首次部署：

~~~bash
cp .env.example .env
# 填写生产环境配置
docker compose up -d --build
docker compose ps
~~~

更新代码：

~~~bash
git pull origin main
docker compose up -d --build
~~~

只修改后端环境变量时：

~~~bash
docker compose up -d --force-recreate backend
~~~

生产前端由 Nginx 提供静态文件，后端和 PostgreSQL 不直接暴露公网。正式环境应在外层配置 HTTPS、域名、访问日志和备份策略。

## 5. 健康检查和日志

~~~bash
curl http://localhost/health
docker compose ps
docker compose logs --tail=200 backend
docker compose logs --tail=200 frontend
docker compose logs --tail=200 postgres
~~~

健康检查返回 status 为 ok 才表示后端进程可用；还需要检查 PostgreSQL、模型 API 和反向代理是否正常。

## 6. 构建依赖问题

后端 Dockerfile 已为 pip 配置清华镜像、300 秒超时和 10 次重试。完整构建日志：

~~~bash
docker compose --progress=plain build --no-cache backend frontend
~~~

如果出现 files.pythonhosted.org 或镜像源 ReadTimeoutError：

1. 检查服务器能否访问当前镜像源。
2. 如果学校有内部 PyPI 镜像，将 backend/Dockerfile 中的 -i 地址换成内部镜像。
3. 网络恢复后重新构建。
4. 构建成功后再执行 docker compose up -d。

这类错误通常是依赖下载超时，不是业务代码错误。

## 7. 数据和清理

- PostgreSQL 数据保存在 postgres-data volume。
- 后端启动时执行一次数据维护，运行期间每 24 小时执行一次。
- 云端草稿默认保留 30 天。
- 终态生成任务默认保留 30 天。
- 管理员审计日志默认保留 180 天。
- 账号每日配额在跨过自然日后清零。

正式环境需要定期备份 PostgreSQL，并定期验证备份恢复。备份文件也应按隐私要求保存和销毁。

## 8. 常见问题

### 容器启动后反复重启

先查看 backend 日志，重点检查 DATABASE_URL、POSTGRES_PASSWORD、AUTH_SECRET、管理员密码和模型 API Key。

### 前端能打开但接口失败

检查生产构建是否使用 /api，Nginx 是否代理 /api 到 backend，以及 FRONTEND_ORIGINS 是否包含实际访问地址。

### 报告生成失败

检查模型通道、API Key、网络出口和任务日志。任务失败不会生成备用模板，需要修复配置后重新提交。

### 语音转写不可用

确认 SPEECH_PROVIDER、讯飞三项密钥、HTTPS 麦克风权限和语音每日配额；默认 disabled 是正常状态。
